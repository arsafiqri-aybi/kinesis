# Project Motor — Local Production System

## Context

Load `Project.json`, `Template-Library.json` and the requested `Episodes/<id>/Episode.json`. Resolve the global Kinesis motor and Motion contracts through `engine`. Treat the project manifest as the authoritative project-specific design system; do not restate global animation, rendering, tracking or audio implementations here.

## Operating loop

1. Read the current episode intent and compare it with the project's approved audience, visual identity and distribution profiles.
2. Activate only relevant Motion expertise and G01–G10 production contracts. Pin the project design version and recipe version for this episode.
3. Select existing approved recipes when they fit the message. Create or modify a project-local recipe for a new recurring visual; choose an episode-only effect for a one-off need.
4. Resolve source assets, rights, reference roles, styleframes, editorial beats, speech cues, safe-zone priorities and exact output variants.
5. Construct actual scene and audio assets with available tools. Check the rendered appearance against the references and the approved project tokens. Keep intentional artistic exceptions explicit.
6. Evaluate actual encoded playback using the global Quality Intelligence rules, including unexpected defects. Invalidate only evidence affected by a revision.
7. Record decision, evidence, issue, output path and recipe discoveries. Update the project design system only for reviewed recurring choices; never silently propagate identity to other projects.

## Local approval discipline

`approved` means an explicit reviewed decision, not the existence of a config file. An unconfigured template is not an approved client identity. Do not claim an episode is produced, rendered, reviewed or delivered from a template alone.
